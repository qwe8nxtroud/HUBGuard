# HUBGuard · автосписок сканеров

Машинно-поддерживаемый чёрный список IPv4, которые **сканировали ноды** (стучались на закрытые порты).
Нужен, чтобы ноды под [HUBGuard](https://github.com/qwe8nxtroud/HUBGuard) резали таких превентивно,
а не ждали локального автобана. По смыслу — как blocklist.de / FireHOL: список источников, опознанных
**по их собственному поведению** против нашей инфраструктуры. Персональных данных тут нет.

## Файлы
- `scanners.txt` — сам список. Один IPv4 на строку, inline-комментарий с датами и статистикой.
- `allow.list` — адреса и подсети, которые **никогда** не попадают в список (канал исправления ошибок).

## Как сюда попадают
Нода-сенсор читает события `[UFW BLOCK]` (попытки соединения на закрытые порты — там нет легального
сервиса, поэтому это почти наверняка сканирование) и публикует источник, только если он:
- бил по закрытым портам **повторно** (не одиночный залётный пакет);
- задел несколько разных портов **или** появлялся в разные дни;
- не приватный/служебный адрес, не из нашей инфраструктуры, не в `allow.list`.

Публикуются **только одиночные адреса**, никогда не /24. Запись живёт **30 дней** с последней поимки,
потом выпадает сама (сканеры меняют адреса, вечный список копит чужие переназначенные). Полностью
адрес убирается из истории через 60 дней бездействия.

## Как подключить на ноде
Нода с HUBGuard тянет список в набор `feed4` (дроп, но всегда через локальный белый список):
```bash
export HG_FEEDS="https://raw.githubusercontent.com/qwe8nxtroud/HUBGuard/blocklist/blocklist/scanners.txt"
sudo -E ./hubguard.sh feed      # по cron, например каждый час
```
Локальный белый список ноды всё равно проверяется первым — свой адрес и доверенные сети не забанятся.

## Ошибочно попал адрес?
Добавьте его (или подсеть) в `allow.list` — сборщик при следующем проходе уберёт его из `scanners.txt`
и больше не опубликует. Или заведите issue.

## Оговорки
- Список публичный: видно, какие адреса мы считаем сканерами. Это нормально (так же открыты blocklist.de и т.п.).
- Адреса за NAT/CGNAT могут собрать чужую активность — поэтому список по умолчанию с коротким сроком жизни,
  только одиночные адреса и с каналом исправления через `allow.list`.
- Это список для **своей** защиты (firewall drop). Никаких действий против самих адресов он не подразумевает.
